# Task Graph Runtime Dogfood 记录 - 2026-06-17

## 状态

本文档记录 Phase 08 真实模型 dogfood 清单。当前已完成自动化/fake-model 覆盖，包括真实 goroutine node 并行和 race 测试。真实模型端到端运行待在具备有效模型配置和本地 CLI 环境时执行。

## 当前开发成果摘要

- Planner 已能输出 `TaskGraphPlan`，并把 task acceptance / required capabilities / final output contract 合并到一次规划结果中。
- Session graph model 已支持 node status、depends、attempts、outputs、evidence refs、verified result 和 recovery state。
- Node Executor 已支持 `direct`、`react`、`skill`、`tool/script`、`human` 路由。
- Node verifier 已支持 passed/retry/failed/blocked/needs_input/replan，并能把 verifier feedback 写回 node retry。
- Local replan 已具备最小闭环：替换 failed/blocked node 及 downstream pending nodes，保留 completed upstream nodes。
- Trace 已覆盖 planner、scheduler、node、tool、verifier、finalizer、memory observe，并包含 `task_id`、`graph_id`、`node_id`、`attempt`。
- Session recovery 已能跳过 completed verified node，恢复 running/retrying node，并保留 awaiting input。
- Skill discovery 已切换为 metadata-only，裸 `SKILL.md` 不参与 runtime discovery。
- Memory observe 已消费 GraphMemorySummary，记录 node attempts、failure、skill usage 和 evidence refs。
- Scheduler 已支持 `execution.max_parallel_nodes`，并对 selected ready nodes 做本地 goroutine 并行；high-risk/human/mutation node 独占批次。
- `go test -race ./internal/runtime` 已通过。

## 是否进入真实模型测试

结论：可以进入真实模型 dogfood，但不应直接做大任务压力测试。建议按本文 10 个场景从简单到复杂逐项运行，并在每项后检查 trace/session/memory。

进入条件：

- 自动化测试通过：`go test ./...`。
- 并发安全检查通过：`go test -race ./internal/runtime`。
- 本地配置中默认模型可用。
- 默认 workspace skills 已有 `.mateway/metadata.yaml`。

首轮真实模型测试建议保持：

- `execution.max_parallel_nodes: 1` 先跑通完整链路。

- 不先跑高风险写入任务；human confirm 场景用临时 scratch 文件。

### Codex follow-up 修复

S8 复测已经确认 skill node 链路修复完成。S2/S6 复测暴露了更准确的 Phase 04 缺口：verifier 直接返回 `failed` 时，runtime 不会进入 bounded local replan。

已补代码侧行为：

- `needs_replan` 继续触发 bounded local replan。
- `failed` 的 `model/subtask/skill` node 也触发 bounded local replan。
- `tool/script/human` 等硬边界失败不自动 replan，保持 failed/blocked 收口，避免把缺工具或人工节点错误替换成 direct repair node。
- 新增单测覆盖 direct verifier failure -> `local_replan_applied`，并保留 retry exhausted -> local replan 覆盖。

下一轮只需复测 S2/S6：

- 如果 verifier 直接给 `failed`，trace 也应出现 `local_replan_start` / `local_replan_applied`。
- 如果 replacement node 再失败，trace 应出现 `local_replan_limit_reached`，不应无限循环。

### 运行环境

- 命令：`go run ./cmd/mateway ask -session "cli:dogfood-scenario<N>"`（S7 用 `chat --classic` + external kill + `ask` resume）
- 配置：`max_parallel_nodes=1`, `max_iterations=50`, `max_parallel_tools=4`
- 模型：`minimax` (MiniMax-M3 via Anthropic API), fallbacks `glm-4.7-flash` / `glm-4.6v-flash`
- 总用时：~15min（含 S7 背景进程 kill + resume + S8 超时）

### 发现的主要问题

1. **verifier 截断判断过严** (S2, S3, S8): model 生成 >5k chars 报告时 verifier 高频判 "output truncated, cannot verify completeness"；max_attempts=2 不够用。
2. **react loop 无 allowed_tools 限制时失控** (S8): `gather_context` 30 次 terminal.run 扫全仓库；planner 未设置 allowed_tools，react node 无工具边界。
3. **local replan 路径未触发** (S6): `node_retry_exhausted` 后 graph 直接 `graph_finalized`(failed)；Phase 04 replan 未检测 exhausted 事件或未接在主调度循环中。这是 P1 路径缺口。
4. **跨 session task fork 无法自动关联 context_refs** (S10): `continuation_decision` context_refs=null；不同 session key 下 runtime 不解析跨 session 的历史 task/node/evidence。
5. **recovery 正确但 running node 被重复执行** (S7): discover-md-files trace 已 completed 但 session 未保存完成状态（crash-between-execute-and-save）；recovery 按 running→pending 语义重新执行成功。行为符合设计（只有 completed+verified nodes skip），但值得考虑：是否在 resume 前先检查 trace evidence 避免浪费。
