# Mateway 测试文档

更新时间：2026-05-20

## 目的

这份文档用于记录 Mateway 的真实模型回归测试流程，并把每个测试任务的设计、执行方式和判定标准固定下来。

目标不是做单元测试，而是验证整套运行机制是否连通：

- 命令入口是否正常
- runtime 主链是否正常
- session/task 绑定是否正常
- 本地文件读取、总结和 trace 记录是否正常
- 连续任务是否能复用同一 session
- 最终是否能在 `testdata/YYYY-MM-DD/` 下生成一任务一文档的结果

## 执行方式

统一使用：

```bash
go run ./cmd/mateway test --title "任务名" --question "任务描述"
```

建议在需要验证连续会话时，显式指定相同的 `--session-key`。

默认输出位置：

- `./testdata/YYYY-MM-DD/`

每个任务都会生成一份 Markdown 报告，报告标题直接使用任务名。

## 判定标准

每个任务至少要满足以下条件：

1. 能调用真实模型，不走假数据。
2. 能完成 runtime 主链或在合理边界内停在待确认/待补问状态。
3. 能生成清晰的 Markdown 报告。
4. 报告中能看出问题、结果、结论、执行过程和参数。
5. 如果任务失败，报告中要能定位失败发生在哪一步。

## 任务列表

### 任务 1：基础运行体检

- 任务名：`基础运行体检`
- 目的：验证最基本的模型调用、计划生成和最终回复是否正常。
- 问题描述：
  - 请检查当前运行环境是否正常，说明你看到的配置、模型和可用工具情况，并给出一句结论。
- 关注点：
  - `doctor` 所反映的配置是否能被 runtime 正常继承
  - 模型是否能输出可读结论
  - Trace 是否完整

### 任务 2：本地文档读取

- 任务名：`本地文档读取`
- 目的：验证 `file.read` 和项目理解路径是否正常。
- 问题描述：
  - 请阅读 `README.md` 和 `docs/README.md`，概括 Mateway 当前的核心架构、命令入口和测试入口。
- 关注点：
  - 文件读取是否受路径边界保护
  - 模型能否正确总结本地文档
  - 是否能把测试入口也纳入总结

### 任务 3：项目风险识别

- 任务名：`项目风险识别`
- 目的：验证模型能否在现有代码和文档基础上提出合理风险点。
- 问题描述：
  - 请根据当前仓库的文档和运行机制，列出最值得优先验证的三个风险点，并说明每个风险点的依据。
- 关注点：
  - 模型是否能把 runtime、session、trace、feishu 等边界理解正确
  - 结果是否有可执行的风险判断

### 任务 4：连续会话复用

- 任务名：`连续会话复用-1`
- 目的：验证同一 session key 下的任务状态能否被复用。
- 问题描述：
  - 先完成一个短任务：用一句话总结当前系统最重要的测试目标。
- 关注点：
  - 生成的 session state 是否可被下一轮接续
  - task 记录是否正确写入

- 任务名：`连续会话复用-2`
- 目的：验证 followup / session 绑定是否能接上上一轮。
- 问题描述：
  - 继续上一轮，把刚才的总结压缩成三条，并说明下一步该优先检查什么。
- 关注点：
  - 相同 `--session-key` 是否能触发上下文延续
  - 是否能看出历史任务被正确加载

### 任务 5：2026 最新 AI 开源课程搜集

- 任务名：`AI开源课程-2026`
- 目的：验证 web 搜索、最新信息判断和来源对比能力。
- 问题描述：
  - 请搜集 2026 年最新、最值得关注的 AI 开源课程，优先选择官方课程页或官方仓库，并说明为什么它们算“最新”或“最热”。
- 关注点：
  - 是否优先使用 2026 的最新来源
  - 是否能区分课程页、仓库页和二手转载
  - 是否能给出可复核的链接和简短依据

### 任务 6：AI 热门趋势搜集

- 任务名：`AI热门趋势-2026`
- 目的：验证趋势搜集、信息归纳和来源引用能力。
- 问题描述：
  - 请总结 2026 年当前最热的 AI 趋势，至少覆盖 open-source AI、agentic AI、AI security / provenance、multimodal 或 audio AI 相关方向。
- 关注点：
  - 是否使用最新一手或权威来源
  - 是否能把趋势说清楚而不是只堆关键词
  - 是否能指出趋势背后的证据

### 任务 7：北京与天津天气

- 任务名：`北京天气`
- 目的：验证天气工具和地点解析是否正常。
- 问题描述：
  - 查看北京当前天气和未来几天预报，给出适合出行的简短建议。
- 关注点：
  - 天气数据是否及时
  - 结果是否简洁可读

- 任务名：`天津天气`
- 目的：验证同类地点的连续查询和结果对比能力。
- 问题描述：
  - 查看天津当前天气和未来几天预报，给出适合出行的简短建议。
- 关注点：
  - 是否能直接查天津而不是混成北京
  - 是否能看出两地差异

### 任务 8：修复后回归测试

- 任务名：`修复后回归`
- 目的：验证刚修复的 followup、trace 对齐和质量提示是否真的生效。
- 问题描述：
  - 运行一组连续会话和 followup 任务，检查“继续上一轮”是否能稳定接上，报告里的 trace 是否能对齐真实事件，任务结论是否更容易看出质量差异。
- 关注点：
  - followup 是否还会频繁掉进 ambiguous
  - trace_id 是否与 runtime 真正对齐
  - 报告是否能反映答案质量风险

### 任务 9：本地读写与命令执行

- 任务名：`本地读写执行`
- 目的：验证本地文件读写、patch 和 shell 命令执行是否正常。
- 问题描述：
  - 读取一个本地文件，做一次小改写，再执行一个本地命令，并把结果写入测试报告。
- 关注点：
  - file.read / file.write / file.patch / shell.run 是否都可用
  - 路径边界和危险命令拦截是否正常
  - 修改后的结果是否能被准确记录

### 任务 10：批量命令组合测试

- 任务名：`批量命令组合`
- 目的：验证连续调用多个工具时的计划、执行、总结是否稳定。
- 问题描述：
  - 先读取本地文档，再执行一个安全 shell 命令，最后总结结果并说明每一步是否成功。
- 关注点：
  - 多工具顺序执行是否稳定
  - 输出是否被截断得足够合理
  - 报告是否足够方便排障

## 结果归档

执行完成后，每个任务都应在以下目录留下独立文档：

```text
testdata/YYYY-MM-DD/
```

文件名建议包含时间戳和任务名，方便按任务快速定位。

## 建议检查项

完成一批任务后，优先检查：

- 是否有任何任务卡在 `await_confirm` 或 `await_user_input`
- `runtime.receive / runtime.plan / runtime.tool_start / runtime.tool_done / runtime.reply` 是否都出现
- session 是否按预期保存
- 报告中的 trace 事件是否和最终结论一致
- 外部信息任务是否尽量选取 2026 最新来源，而不是旧网页或旧季度材料
- 北京 / 天津天气是否能区分地点而不混淆
- 修复后回归是否真的把历史问题压住了
