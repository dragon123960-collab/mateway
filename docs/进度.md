## v0.1.4 Baseline

## 最近完成

- M1 Hook Skeleton：已接 Runtime hook provider、timeout、panic/error recovery、trace warning；`context_hook` 已复用 runtime system context。
- M2 Memory Safe Read：已实现 Markdown frontmatter lint、`memory index rebuild`、`memory search`，并通过 `context_hook` 注入短摘要和 source refs。
- M3 Proposal Workflow：已实现 `memory proposal create/list/reject/commit`，proposal 与 audit 写入 `observe/`，active memory 只在显式 commit 时写入。
- M4 Self-learning Worker：task completed 后写 diary；失败/可疑 step 写 reflection；高价值任务生成 proposal 并在最终回复展示具体候选和操作命令。
- M5 Distillation Boundaries：已实现显式 `mateway memory distill session <session-key>`，只生成 session reflection，不修改 session/task 状态，不误判 task completed。
- Hook Consolidation：`context_hook / followup_hook / tool_policy_hook / observe_hook / response_hook` 已统一进入 provider 链，均有 trace event/warning 与失败降级。
- Project Distillation：已实现显式 `mateway memory distill project close <project_id>`，只生成 project reflection 和 audit，不自动归档或改写 active memory。
- Heartbeat：已实现 `mateway memory heartbeat lint-index` 和 `mateway memory heartbeat serve`，顺序执行 lint + index rebuild，并写 audit。
- Schedule：已实现 channel-neutral `mateway schedule create/list/test/activate/pause/run-due/serve`。默认先 pending，试跑成功后 active；飞书里创建定时任务后会询问是否现在试运行，用户回复“执行”且试运行成功后才激活；到点执行只写 run record，不内置飞书/邮件/Slack 投递。
- Visualization：已实现只读 `mateway memory report`，汇总 memory files、index entries、issues、proposal 状态和 observe ledger 数量。
- Memory Cleanup：旧 `~/.mateway/workspace/memory` 已移动备份到 `memory.backup-before-clean-20260529-144533`，重新初始化干净 memory wiki；lint 0 issue、index 1 entry、search/heartbeat/project close 均通过。
- Memory Scan Scope：`inbox/`、`recent/`、`learning/`、`.obsidian/` 默认不参与长期 memory lint/index，避免候选/临时工作区阻塞 active memory；长期记忆正文仍严格校验 schema。
- Feishu 体验：快速 ack、message_id 去重、忽略 self/app/bot 消息、reaction 状态、友好错误。
- Followup：短问句如“天津呢”会续接最近任务；“重试/再试一次”会复用最近任务。
- Prompt context：注入当前时间/时区、系统环境、workspace profile/user/tools 摘要、实时信息判断策略。
- Observability：trace 记录 request、model、tool、reply、runtime；新增 `mateway trace <trace-jsonl-path>` 汇总耗时。
- Search：`web.search` 已压缩成结构化摘要。
- Search：`web.fetch` 对 Hacker News 首页类 URL 已接 HN Algolia fallback。
- Skills：第一版 discovery 已接入；skills 不作为可执行 tool，不改变单 agent 主线。
- Learning Proposal：已实现 learning evidence ledger、skill usage ledger、learning heartbeat、skill patch proposal、proposal promote/reject。
- Script Bridge：已实现脚本发现、`script.run`、required secret 注入和 evidence。
- Multi-Agent Profile：已实现 `agent list/report/lint/create/bind/unbind`，AgentPool 支持 channel/account/peer binding。
- Agent Core Profile：`soul.md` 已纳入 core prompt 文件；`init` 和 `agent create` 都生成 `agent.md/soul.md/user.md/tools.md/memory.md`。
- Internationalization：已实现 `app.locale`、内置 `en-US`/`zh-CN` message + alias catalog、外部 YAML catalog、双语 aliases，以及首批 runtime/Feishu 用户文案迁移。
- Reports：已实现 `memory report`、`memory learning report`、`skill usage report`、`workspace report`、`sandbox report`、`agent report`。
- HOME：init 会建立当前最小 HOME 目录；完整目标结构见 `docs/HOME目录结构.md`。

## 当前问题

- 真实任务耗时需要继续观察，主要耗时在模型侧。
- 第一轮 i18n 已加入 `app.locale`、message + alias catalog、英文/中文内置文案、外部 YAML catalog、双语确认词和首批 runtime/Feishu 文案迁移；剩余问题是继续抽出少量友好错误、`/new` reply 和 proposal nudge。
- init 已种下少量默认 shared skills；已有 HOME 不会被 init 覆盖，后续如需同步默认 skill，需要单独设计 sync 命令。
- 两个 `memory.md` 已明确分工：`workspace/agents/main/memory.md` 是 prompt-facing 短摘要，`workspace/memory/agents/main/memory.md` 是长期记忆 wiki 入口。
- 邮件、远程服务器运维、自媒体发布仍没有完整 connector framework；当前策略是优先通过 Script Bridge、已有 CLI/配置、脚本/API 方案接入，不能编造完成。
- 当前没有 `~/.mateway/logs` 文件日志；可观察性依赖 trace JSONL，launchd 承接 gateway stdout/stderr。
- 当前没有完整 OS-level sandbox；已有 workspace path policy、危险命令确认、terminal sandbox wrapper 配置、sandbox report 和文件大小/binary guard。
