# Mateway 项目运行机制

## 1. 项目定位

Mateway 现在是一个以 `internal/harness` 为核心的消息驱动助理宿主。

它负责三件事：

- 接收消息并把它变成任务
- 用统一 runtime 执行任务
- 把结果、记忆、日志、失败经验沉淀下来

当前主要入口是飞书，也支持本地 `tui`。主运行时是 Eino。

## 2. 主执行链

一条典型任务会按下面的顺序流转：

1. 渠道入口接收消息  
   飞书先把消息分成 `control / approval / follow_up / new_task`。

2. Harness 创建 Run  
   `Harness.Start` 生成：
   - `run_id`
   - `task_id`
   - `task_type`
   - `route`
   - `visible_tools`
   - `selected_skills`

3. 任务分类  
   当前任务类型包括：
   - `answer`
   - `research`
   - `code_read`
   - `code_write`
   - `local_cli`
   - `tool_task`
   - `schedule_task`
   - `memory_task`
   - `delegate_task`
   - `diagnose_task`

4. 路由选择  
   默认优先级是：
   - `research / diagnose_task` 倾向 `plan_execute`
   - `schedule_task / local_cli / memory_task / tool_task / delegate_task` 倾向 `chatmodel`

   注意：如果当前配置模型不适合 `plan_execute`，系统会保护性退回 `chatmodel`。

5. 选择 skill 与工具  
   - skill 先走 heuristic，再按需模型挑选
   - 工具按任务目标打分，不是全量盲选
   - schedule 查询优先 `schedule_list / schedule_get / schedule_runs`
   - 本机 CLI 查询优先真实本地环境线索，而不是先用沙箱猜

6. 执行与恢复  
   - chat/tool 都会写 `RunStep` 和 `RunEvent`
   - 模型调用有 `model_attempt`
   - 429 有 limiter 和 cooldown
   - 常见失败会进入恢复逻辑或 lesson 沉淀

7. 结果收口  
   顶层任务会收敛到一份完成契约：
   - `status`
   - `summary`
   - `primary_artifact`
   - `secondary_artifacts`
   - `evidence`
   - `next_action`

8. 记忆与复盘  
   - 写任务主档
   - 更新 session summary
   - 写 run 记录
   - 写结构化 lesson
   - 必要时写精选 wiki 页

## 3. 任务、记忆、结果一体化

现在的主线已经改成“单任务主档”模型。

核心对象：

- `Run`：执行遥测，记录这次具体跑了什么
- `TaskRecord`：任务主档，记录这次任务最终是什么、结果是什么、证据是什么
- `CompletionContract`：任务完成时的统一结果结构
- `LessonRecord`：失败经验和恢复策略

原则：

- `run_id` 负责追踪执行
- `task_id` 负责回答“这次任务最终是什么结果”
- 用户追问“成果在哪”“为什么失败”，优先看 `TaskRecord`

## 4. 当前 memory 目录说明

`workspace/memory/` 现在主要分成下面几层：

### 短期记忆

- `memory/sessions/`  
  原始对话 transcript，append-only。

- `memory/summaries/`  
  当前会话摘要。现在不是只存对话摘要，而是会指向最近两个任务主档。

### 执行记录

- `memory/runs/`  
  每个 `run_id` 一份 JSON，最完整的执行轨迹。

- `memory/logs/`  
  结构化 JSONL 日志，适合按 run/session/type 过滤。

- `memory/reflections/`  
  较轻量的运行反思与统计记录。

### 新的一体化主层

- `memory/tasks/`  
  每个 `task_id` 一份主档，是结果真相来源。

- `memory/task_outcomes/`  
  轻量任务结果索引，方便按会话、任务类型、状态快速查。

- `memory/artifacts/`  
  产出物索引，记录文件路径、引用对象、run/task 关系。

- `memory/lessons/`  
  结构化失败经验。重点看：
  - `failure_kind`
  - `tool_name`
  - `provider_name`
  - `preferred_fallback`
  - `do_not_repeat`

### 定时任务

- `memory/schedules/jobs.json`  
  所有定时任务定义。

- `memory/schedules/runs/*.jsonl`  
  每个 schedule 的运行历史。

说明：
- 每次 schedule 触发都会创建一个新的顶层 `TaskRecord`
- schedule job state 里会记录 `last_task_id`

### 学习与精选知识

- `memory/learning/proposals/`  
  学习提案，等待批准落盘。

- `memory/learning/reports/`  
  每次高价值任务的正式复盘报告。

- `memory/wiki/`  
  精选知识库，只保留长期有复用价值的概念页、经验页、故障模式页、操作指南页。

当前约束：
- 不再为每个 completed task 自动生成 wiki 页面
- 但 failure lesson 目前仍可能额外生成一份精选 wiki 故障页

## 5. 定时任务的特殊规则

定时任务最容易让人搞不清楚“有没有执行”“成果在哪”，所以单独记：

- 定时任务定义看 `memory/schedules/jobs.json`
- 每次执行历史看 `memory/schedules/runs/*.jsonl`
- 最近一次真正产出看对应 `last_task_id` 的 `memory/tasks/*.json`

所以：

- “这个任务有没有执行”  
  先看 `jobs.json` 和 `schedules/runs/*.jsonl`

- “这个任务成果在哪”  
  先看 `last_task_id` 对应的 `memory/tasks/*.json` 里的 `primary_artifact`

## 6. 成功、失败、部分完成如何判断

### 成功

一个顶层任务想算真正完成，至少应该有：

- `status = completed`
- `summary`
- `evidence`

对于这些任务，还应该有 `primary_artifact`：

- `schedule_task`
- `code_write`
- `diagnose_task`

### 部分完成

如果有答复，但没有足够证据或没有明确产出物，会降为 `partial`。

### 失败

失败时通常会同时留下：

- `memory/runs/<run_id>.json`
- `memory/logs/*.jsonl`
- `memory/lessons/*.json`
- 有时还有 `memory/wiki/notes/failure-*.md`

## 7. 常用排查顺序

### 用户问“最近任务是什么”

先看：

1. `memory/summaries/<session>.json`
2. `memory/tasks/` 最近更新的 task record

### 用户问“成果在哪”

先看：

1. `memory/tasks/<task_id>.json` 的 `primary_artifact`
2. `memory/artifacts/<task_id>.json`
3. schedule 场景下，再看 `memory/schedules/jobs.json`

### 用户问“为什么失败”

先看：

1. `memory/tasks/<task_id>.json`
2. `memory/runs/<run_id>.json`
3. `memory/logs/*.jsonl`
4. `memory/lessons/*.json`

## 8. 清空并重建 memory

本项目现在支持显式重建 memory：

```bash
mateway memory rebuild --force --drop-all
```

作用：

- 删除当前 workspace 下整个 `memory/`
- 按新结构重新建目录

注意：

- 这是破坏性操作
- gateway 启动时不会自动删数据
- 真要切到一套全新记忆，先执行这条命令，再重启 gateway

## 9. 你只想快速理解项目时，先看什么

如果你只想一次整明白项目怎么跑，按这个顺序看：

1. 本文档
2. `docs/飞书测试与验收.md`
3. `AGENT.md`
4. `TODO.md`

如果你要看代码主链，优先看：

- `internal/harness/harness.go`
- `internal/harness/eino_runtime.go`
- `internal/harness/eino_middleware.go`
- `internal/channels/feishu/handler.go`
- `internal/memory/store.go`
- `internal/memory/task_records.go`
