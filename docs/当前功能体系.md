# Mateway 当前功能体系

更新时间：2026-05-21

## 总体判断

Mateway 目前已经形成了一个可运行的单 Agent 工具体系：

```text
CLI / Feishu
-> Gateway
-> Runtime AgentLoop
-> ToolRegistry / SkillRegistry
-> Session + Memory + Schedule
-> Final Reply / Artifact
```

它已经不是零散功能集合，而是一个小型闭环：

- 可以通过 CLI 和 Feishu 接收请求。
- 可以规划、调用工具、确认高风险动作、总结回复。
- 可以保存 session/task 状态并处理 followup。
- 可以沉淀短记忆、长期记忆 proposal、skill candidate。
- 可以通过 Markdown LLM Wiki 检索和引用长期记忆。
- 可以运行系统 heartbeat 和用户业务定时任务。
- 可以通过 LaunchAgent 常驻运行 `gateway serve`。

当前仍然是单 Agent 主链。多 Agent 配置契约已存在，但 Gateway 多 Agent 路由、supervisor、spawn/subagent、DAG 编排仍未进入当前实现范围。

## 已形成的核心闭环

### 1. Agent Runtime

已完成第一版：

- `Runtime.Handle()` 启动 `AgentLoop`
- `receive -> plan -> act -> repair -> synthesize -> reply`
- 统一工具执行、一次 plan repair、结果截断、最终 reply sanitizer
- 高风险工具进入确认流
- 待补问、待确认、取消确认都有 session 状态
- trace 写入 `~/.mateway/trace/events-YYYY-MM-DD.jsonl`

关键代码：

- `internal/runtime`
- `internal/model`
- `internal/tool`
- `internal/observer`

### 2. Session / Followup / Artifact

已完成第一版：

- session 存储在 `~/.mateway/run/sessions`
- session key 按 channel 隔离，例如 `cli:*`、`feishu:*`
- task state 记录 active task、pending approval、pending questions、artifacts
- followup resolver 支持继续、展开、重试、历史任务 continuation
- 窄意图下可直接回答历史产物路径或链接

关键代码：

- `internal/session`
- `internal/followup`
- `internal/runtime/task_binding.go`
- `internal/runtime/artifact_answer.go`

### 3. Tool / Skill

已完成第一版：

- 内置工具注册表
- 工具风险分级
- 危险命令和写文件确认边界
- 路径限制和输出预算
- workspace skill discovery 和默认 skill 注入

当前内置工具包括：

- `time.now`
- `config.summary`
- `web.search`
- `file.read`
- `file.write`
- `file.patch`
- `shell.run`

- `file.summary`

关键代码：

- `internal/tool`
- `internal/skill`

### 4. Memory / LLM Wiki

已形成第一版完整闭环：

```text
session short memory
-> long memory search
-> task success evidence
-> memory proposal inbox
-> user commit
-> long memory
-> JSON index rebuild
-> search/index tools
```

当前能力：

- Markdown 是真相源，位于 `workspace/memory`
- long memory proposal / commit / reject
- inbox reminder
- 自动 memory proposal，只写 inbox，不自动 commit
- 结构化 YAML frontmatter parser
- source evidence parser
- `memory lint`
- `memory index`
- `workspace/memory/index.json` 可从 Markdown 重建
- `SearchLong` 优先使用 index 过滤候选，再回读 Markdown
- prompt 注入相关 long memory，带 path/line evidence
- `memory.search` 和 `memory.index` 工具可被 runtime 显式调用
- memory propose / commit / reject 后 best-effort rebuild index
- heartbeat 可运行 `memory_index_rebuild`

关键代码：

- `internal/memory`
- `internal/runtime/short_memory.go`
- `internal/runtime/long_memory.go`
- `internal/runtime/memory_proposal.go`

### 5. Heartbeat

已完成第一版：

- quiet hours 生效
- 自动 job 白名单仅允许低风险维护任务

关键代码：

### 6. User Scheduled Tasks

已完成第一版骨架：

```text
natural language schedule request
-> draft / missing slots
-> proposal
-> user confirmation
-> active task
-> scheduler due detection
-> Runtime.Handle scheduled invocation
-> artifact output
```

当前能力：

- YAML task store：`~/.mateway/schedules/tasks/*.yaml`
- YAML proposal store：`~/.mateway/schedules/proposals/*.yaml`
- JSON run state：`~/.mateway/run/scheduler/user_tasks_state.json`
- CLI create/propose/list/show/pause/resume/delete/due/run-due
- runtime 自然语言创建、确认、拒绝
- 删除 / 暂停 / 恢复需要确认
- 修改 schedule spec / prompt 需要确认
- daily / weekly / interval / monthly
- workday / multiple weekdays 第一版抽取
- due task 通过 runtime 主链执行
- 第一版 delivery 只写 artifact，不主动发 Feishu

关键代码：

- `internal/schedule`
- `internal/runtime/schedule_request.go`
- `internal/gateway/gateway.go`

### 7. Gateway / Feishu / Service

已完成第一版：

- CLI `ask`
- Feishu WebSocket receive/reply/reaction
- message id dedupe
- app/self message ignore
- slow runtime 后台执行，不阻塞 WebSocket callback
- `gateway serve` 是真实前台服务进程
- macOS LaunchAgent 管理适配
- 单实例锁：`~/.mateway/run/mateway.lock`
- `scripts/restart-plist.sh` 可 build 并重启已有 LaunchAgent

关键代码：

- `internal/channel/feishu`
- `internal/gateway`
- `cmd/mateway`
- `scripts/restart-plist.sh`

## 当前如何启动

如果 LaunchAgent 已经安装，且 plist 指向当前仓库的 `build/mateway gateway serve`，可以用：

```bash
scripts/restart-plist.sh --env-file ~/.mateway/config/mateway.env
```

这个脚本会：

- source 指定 env 文件
- build `build/mateway`
- `launchctl kickstart -k gui/$(id -u)/com.dongping.mateway.gateway`

它不会：

- 创建 plist
- 安装 plist
- 修改 plist

`gateway serve` 启动后是否运行全部后台能力，取决于配置：

- Feishu 需要 channel 配置 enabled 且凭证正确。
- heartbeat scheduler 需要 `scheduler.enabled=true` 且 agent `heartbeat.enabled=true`。
- 用户业务定时任务需要 `scheduler.enabled=true`。
- heartbeat job 需要写在 agent heartbeat jobs 中。

## 是否已经形成完整功能体系

结论：已经形成“单 Agent + 工具 + 记忆 + 定时”的第一版完整体系。

它已经可以支撑日常使用：

- 用户从 CLI/Feishu 提需求。
- Agent 规划并调用工具。
- 高风险动作要求确认。
- 任务状态可持续跟进。
- 结果可形成记忆 proposal。
- 用户审核后进入长期记忆。
- 长期记忆可检索、可引用、可重建索引。
- heartbeat 做系统维护。
- 用户业务定时任务按授权触发 runtime。

但它还不是最终形态。当前完成的是“可用闭环”，不是“完全自动化平台”。

## 主要缺口

### P0：产品化启动和配置体验

- plist 安装/检查命令还不完整。
- `restart-plist.sh` 只能重启已有 LaunchAgent。
- 配置启用状态需要更清晰的 doctor 检查。
- scheduler / heartbeat / Feishu 是否实际启用，需要更明确的 status 汇总。

### P1：Memory 审核和晋升体验

- memory proposal 已能生成/commit/reject，但缺少更好的 review UI/CLI 汇总。
- skill candidate 还没有完整 promote 命令。
- user/org scope 的 long memory 提交路径还可细化。
- source evidence 已结构化，但还没有在最终回答中形成统一 citation 格式。

### P2：User Scheduled Tasks 长尾能力

- date range、timezone、end condition 还未实现。
- delivery 当前只写 artifact，不主动发 Feishu。
- 修改 schedule 的自然语言抽取仍保守。
- next_run_at 还未持久化。

### P3：Connector 扫描注册机制

- larkcli 不内置是当前决策。
- 但 connector 配置扫描、校验、注册工具尚未实现。
- 外部 CLI/API 暴露为工具的安全边界还未落地。

### P4：多 Agent 共存

- AgentProfile 配置契约已有。
- GatewayBinding / AgentRegistry / 多 agent session namespace 运行时接入尚未实现。
- supervisor / spawn / DAG 明确延后。

### P5：检索增强

- 当前使用 Markdown + JSON index + 轻量关键词。
- SQLite FTS5 仍是可选后续，不是当前依赖。
- embedding / rerank / LLM review 都尚未启用。

## 下一阶段建议

建议按这个顺序推进：

1. 做 `mateway status` 或增强 `doctor`，一次性显示 Feishu、gateway、scheduler、heartbeat、memory index、user schedules 状态。
2. 做 memory proposal / skill candidate 的 review/promote CLI。
3. 做 connector 扫描注册机制。
4. 再做 AgentRegistry / GatewayBinding。
5. 最后再评估 SQLite FTS5 或 embedding。
