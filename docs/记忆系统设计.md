# 记忆系统设计

## 总体结论

Mateway 采用 Markdown / Obsidian-compatible LLM Wiki 作为记忆系统。

核心原则：

- Markdown 是真相源。
- SQLite 未来只做可重建索引，不作为唯一存储。
- 每个 agent 有私有记忆。
- `user` 和 `org` 记忆放在统一 `workspace/memory` 根目录下共享。
- 技能沉淀由任务成功事件触发，不依赖半夜定时任务。
- 高影响记忆和 skill candidate 默认需要用户确认。

## 目录结构

```text
~/.mateway/workspace/
  memory/
    README.md
    schema.md
    index.md
    log.md

    user/
      index.md
      profile.md
      preferences.md
      projects/

    org/
      index.md
      systems/
      playbooks/
      terminology/

    agents/
      main/
        memory.md
        index.md
        recent/
        long/
        inbox/
        raw/
        learning/
          patterns.jsonl
          counters.json
          pending_skill_candidates/
```

职责：

- `memory/user/`：跨 agent 的用户偏好和稳定事实。
- `memory/org/`：企业系统、流程、术语、playbooks。
- `memory/agents/<agent_id>/`：agent 私有记忆。
- `memory.md`：prompt 入口和摘要索引，只保留少量高价值摘要。
- `recent/`：近 2-3 天滚动工作摘要。
- `long/`：稳定长期记忆。
- `inbox/`：待确认记忆候选和 skill candidate。
- `learning/`：任务模式计数和技能结晶状态。
- `index.md`：Obsidian 入口和页面索引。
- `log.md`：记忆操作日志。

## Markdown 页面格式

长期记忆页面使用 YAML frontmatter：

```yaml
---
type: project | system | preference | playbook | decision | source | skill_candidate
scope: agent | user | org
owner_agent: main
visibility: private | shared-user | shared-org
status: active | proposed | deprecated
tags: [mateway, memory]
aliases: []
sources: []
confidence: high | medium | low
created_at: 2026-05-20
updated_at: 2026-05-20
---
```

Obsidian 兼容规则：

- 使用 `[[wikilinks]]` 连接知识。
- 使用 `tags` 支持图谱过滤。
- 使用 `aliases` 支持同义词。
- 使用 `sources` 标注来源。
- 使用 `confidence` 标记可信度。

## 读取机制

普通任务读取：

```text
planning 前：
  session/task short memory
  -> agent private memory
  -> user shared memory
  -> org shared memory

synthesis 前：
  只注入本轮实际用到或高度相关的记忆片段
```

followup 判断前：

- 读取 session/task 状态。
- 读取 agent recent memory 摘要。

skill selection 前：

- 读取相关 playbook 或 skill candidate 摘要。
- 不把整库塞入 prompt。

## 写入机制

任务结束后即时触发：

- 记录任务 pattern。
- 更新 skill crystallization counter。
- 达到阈值时生成 skill candidate。
- 生成记忆 proposal。

后台 heartbeat 触发：

- 写 recent daily summary。
- 生成 long memory proposal。
- 写 lint report。
- 不主动询问用户。
- 不默认提交高影响长期记忆。

用户确认后：

```text
inbox proposal
-> long memory page
-> update index.md
-> append log.md
```

## 确认策略

默认需要确认：

- 用户偏好。
- 组织知识。
- 长期记忆。
- 企业流程。
- skill candidate。

可以自动写入：

- recent daily summary。
- inbox proposal。
- log。
- lint report。
- SQLite index 重建。

禁止写入：

- secret
- token
- 密码
- 私密凭据

## 技能结晶

技能结晶不依赖定时任务。

流程：

```text
task completed successfully
-> record pattern
-> update counter
-> count >= success_threshold
-> write skill candidate to inbox
-> ask user on next interaction
-> user confirms
-> promote to workspace/skills/<skill-name>/SKILL.md
```

默认阈值：

```yaml
learning:
  skill_crystallization:
    success_threshold: 3
    require_user_confirm: true
    ask_timing: next_interaction
```

skill candidate 位置：

```text
workspace/memory/agents/main/inbox/skill-candidate-*.md
```

正式 skill 位置：

```text
workspace/skills/<skill-name>/SKILL.md
```

## SQLite 定位

- 用户不需要安装 SQLite 服务。
- 未来可以用 Go 内嵌 SQLite 驱动。
- `index.sqlite` 只做索引层。
- SQLite 损坏时必须能从 Markdown 重建。
