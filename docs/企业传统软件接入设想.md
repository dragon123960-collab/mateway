# 企业传统软件接入设想

## 总体愿景

Mateway 后续可以帮助传统企业把已有 API、CLI、脚本和内部系统包装成 agent 可调用能力。

目标不是做一个大而全 workflow 平台，而是：

```text
传统系统能力
-> connector package
-> tools / fixed workflows / skills
-> agent 调用
-> 用户通过 CLI / 飞书 / 未来 channel 获得结果
```

## Connector Package

建议目录：

```text
connectors/
  crm/
    connector.yaml
    SKILL.md
    tools/
    workflows/
    examples/
```

`connector.yaml` 声明：

- name / version / owner
- tools
- risk
- args schema
- auth requirements
- confirmation boundary
- output evidence schema

## Skill / Tool / Workflow 分工

```text
connector
  描述企业系统能力包

tool adapter
  真正调用 API / CLI / script

skill
  告诉 agent 什么时候用、怎么问、怎么解释结果

fixed workflow
  承接确定性多步骤业务流程
```

## API Adapter

支持把 HTTP API 声明成 tool。

能力：

- method
- url
- headers
- body template
- env secret 引用
- timeout / retry
- response extraction
- risk / confirm

安全边界：

- secret 只来自 env/config，不进入 prompt。
- trace 记录 endpoint 摘要，不记录 secret。
- 参数校验失败时不调用 API。

## CLI Adapter

支持把企业已有 CLI 或脚本声明成 tool。

能力：

- command template
- working directory
- env allowlist
- stdout/stderr budget
- dangerous command boundary

安全边界：

- 防 shell 注入。
- 高风险命令进入确认。
- 输出截断。
- 不打印 secret。

## Fixed Workflow

适用场景：

- 查客户 -> 查订单 -> 查物流 -> 汇总。
- 生成报表 -> 校验 -> 通知。
- 创建工单 -> 添加附件 -> 更新状态。

原则：

- 只用于确定性企业流程。
- 不替代主 AgentLoop。
- 每步可观测。
- 失败可解释并可恢复。

## 与记忆和技能沉淀的关系

企业 connector 的稳定调用方式可以沉淀为：

- org memory
- playbook
- skill candidate
- fixed workflow

沉淀必须有确认边界，不能自动把企业流程静默写成长记忆或 active skill。
