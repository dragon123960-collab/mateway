# Mateway 总规划

更新时间：2026-05-29

## 定位

Mateway 重新开始，目标是一个小而稳定的 Go agent runtime：

```text
Mateway
= CLI / Feishu-ready gateway shell
+ transcript-driven AgentCore
+ small ToolRegistry
+ Session / Memory-ready state boundary
+ multi-agent profile / binding foundation
+ ~/.mateway config layout
```

## 当前固定方向

- 借 `pi` 的 transcript tool-call loop。
- `picoclaw` 的 Go 极简 loop / registry 形态已吸收到当前 `AgentCore + ToolRegistry` 实现中，后续不再作为独立追赶目标。
- `openclaw` 的 channel/session 边界已吸收到当前 `channel / gateway / session` 边界中，后续只保留这个边界原则。
- 保留 Mateway 的 CLI、channel、gateway、config、session namespace。
- 优先通过可编辑 skills 改善行为；prompt/skill 能解决的，不改 runtime。
- Hook、Memory、Heartbeat、Schedule 基础闭环已完成。
- 已预留并部分实现多 agent profile / binding / agent-specific skill / agent-specific memory 目录。
- 下一阶段转入增强已有模块：Multi-Agent Profile 产品化、skill source adapters、script bridge、sandbox runner、只读 workspace UI。
- Memory 通过 hook/event 接入，不替代 session binding，不强耦合 runtime。

## 多 Agent 边界

当前项目不是“只做单 agent”。已存在的多 agent 基础包括：

- `config.agents.default`
- `config.agents.profiles[]`
- `config.agents.bindings[]`
- `AgentPool` 按 channel/session binding 选择 profile
- `workspace/agents/<agent_id>/`
- `workspace/agents/<agent_id>/skills/`
- `workspace/memory/agents/<agent_id>/`

第二阶段要把这套基础产品化：补 `agent list/report/create/bind`、profile lint、真实多 profile 测试、文档和验收边界。

但第二阶段仍然保持小 runtime，不做自主多 agent 编排。多个 profile 是“可配置的工作身份和上下文隔离”，不是 supervisor/subagent/DAG 系统。

## 当前不做

- supervisor
- spawn/subagent
- DAG routing
- gateway 多 agent 业务路由或自动任务分派
- heavy connector framework
- 复杂 skill marketplace 协议
- memory-driven runtime routing
- 完整 PilotDeck 式 Web 平台，先只做 trace/task/memory 的只读透明视图

## 当前已形成的 checkpoint

- `AgentCore` 已具备 transcript tool loop、malformed tool-call 恢复、工具预算耗尽后的最终合成。
- `ToolRegistry` 保持小而硬：`file.read/write`、`project.index`、`terminal.run`、`web.search/fetch`。
- `web.fetch` 对 Hacker News 首页类 URL 有 HN Algolia fallback。
- `init` 会种下少量可编辑 shared skills：`software-install`、`fresh-search`、`source-evaluation`、`connector-gap`。
- skills 是行为指导，不是可执行 tool；runtime 会注入 name/description/stage/priority 和短 guidance。
- connector 缺口优先通过本机探测、脚本、官方 API/CLI 接入方案来补，不急着做完整 connector framework。
- schedule 是 channel-neutral：创建后先试跑，成功才激活；通知由任务本身通过脚本/skill/connector 完成，scheduler core 不绑定飞书或邮件。

## Memory 方向

Memory 是 Hook Skeleton 后的主线。

- Markdown 是长期认知 source-of-truth。
- SQLite、向量库、index 都是可重建增强层。
- Self-learning 属于 Memory，但默认可审计、可确认、可回滚。
- 自动经验写入、经验升 Skill、Skill 修改通过低心智负担 preset 和阈值配置表达。
- 历史任务 followup 先靠 session task tree 精确/半精确绑定；memory search 后续作为辅助证据，而不是替代 session binding。

## 目标主循环

```text
receive
-> gateway session claim
-> runtime setup
-> context_hook
-> AgentCore transcript loop
-> tool_policy_hook
-> tool execute
-> observe_hook
-> response_hook
-> reply
```
